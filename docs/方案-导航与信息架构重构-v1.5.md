# EdenCourt v1.5 导航与信息架构重构方案

> 状态：**草案（待用户审阅）**。本文件所有「倾向/暂定/候选」均为 AI 调研提法，未获用户「彻底完全决定」前不定死。
> 生成背景：v1.3 稳定发布后，用户对信息架构提出 5 点改进意见，要求先出书面方案再动代码。

## 一、需求来源（用户原话归纳）

1. 跳转动画「不太流畅与舒服」
2. 「我自己的身份不应该拎出来吗」——我的身份当前深埋在设置页第 2 区
3. 「弄成类似微信的页面切换会不会好一点」——底部 Tab，从左到右「角色卡 / 会话 / ？ / 设置」
4. 「设置里虽然进行分栏，但是会不会太长了」
5. 「记忆和角色卡部分不好整，尽量参考网络上较成熟的方案」

加上本方案确认的 3 个决策倾向：
- 第 3 个 Tab「？」= **互动中心**（用户点选）
- 我的身份 = **独立底部 Tab「我」**（用户点选）
- 执行前先出书面方案（用户点选）

## 二、现状诊断

| 问题 | 现状 | 影响 |
|---|---|---|
| 单入口导航 | [AppNavHost.kt](../../app/src/main/java/com/bdalxy/edencourt/navigation/AppNavHost.kt) 首页固定为会话列表，其余页面全是二级浮层 | 角色卡/记忆/互动中心都被「藏」进顶栏图标或菜单，发现成本高，用户觉得「不好整」 |

## 三、导航结构方案（核心变更）

### 3.1 底部 Tab 候选

微信式「底部 Tab + 页面滑动切换」是成熟范式：`NavigationBar` + `HorizontalPager` 联动，`animateScrollToPage` 平滑过渡。调研参考见 §7。

**两个候选结构（待确认）：**

| Tab 位置 | 方案 A（4 Tab，倾向） | 方案 B（5 Tab） |
|---|---|---|
| 1 | 角色卡 | 角色卡 |
| 2 | 会话 | 会话 |
| 3 | 互动中心 | 互动中心 |
| 4 | 我（含设置入口） | 我 |
| 5 | — | 设置（独立） |

- **方案 A**：更贴近微信「4 Tab」，也最简洁；「设置」作为「我」Tab 内的一个入口（退出二级页），我的身份是「我」Tab 的主角。
- **方案 B**：设置独立成 Tab，语义最直白，但 5 个 Tab 略多，底部偏拥挤。

> 倾向方案 A：因为「我的身份」与「设置」天然属于「我」这一层，合并后信息架构更收敛。**但这是倾向，等你定。**

### 3.2 各 Tab 内容设计（初稿）

#### Tab 1 — 角色卡（是「陈列 + 管理」的一级页，不再是纯列表）
- 顶部：角色卡片**横向陈列**（大卡片，头像 + 名字 + 简介 + 标签 + 此刻状态），类似星野「智能体广场」的单卡浏览体验（参考 §7.1）
- 下方：已有角色列表 + FAB「新建/导入」
- 点击卡片 → 进既有 `CharacterScreen` 详情编辑（保留现有 `CharacterDetailDialog` / 作息设置，不动）
- 改动量：仅新增一个「横向陈列头」，列表与详情复用现状

#### Tab 2 — 会话（现状首页整体迁入）
- 即当前 [ConversationListScreen.kt](../../app/src/main/java/com/bdalxy/edencourt/feature/conversationlist/ConversationListScreen.kt) 原样作为此 Tab 内容
- 顶栏的「记忆⭐ / 互动❤」图标入口可**弱化或移除**（对应功能已升为独立 Tab，避免重复）
- 聊天页仍是此 Tab 下**二级页**（保留顶部返回，不塞进 Tab）

#### Tab 3 — 互动中心（现状二级页升为一级 Tab）
- 即当前 [InteractionCenterScreen.kt](../../app/src/main/java/com/bdalxy/edencourt/feature/interaction/InteractionCenterScreen.kt) 原样提升
- 移除其「返回」按钮语义（改成 Tab 切换）

#### Tab 4 — 我（新页，我的身份是主角）
- **我的身份卡片**：头像 + 名字 + 称呼 + 一句话自述（顶部醒目展示，可点击进编辑页）
  - 编辑页复用现有 `IdentitySettingsSection` 的逻辑字段（名字/称呼/自述/性格/背景）
- **条目列表**（微信「我」页那种竖向菜单）：
  - 设置（AI API / 角色作息 / 互动中心入口等 → 进瘦身后的设置页）
  - 关于（进现有 `AboutScreen`）
  - （可选）记忆管理入口（若决定记忆不单独成 Tab，可放这里）

## 四、跳转动画方案

| 场景 | 方案（倾向） | 说明 |
|---|---|---|
| Tab 间切换 | `HorizontalPager` 左右滑动 + `animateScrollToPage` | 微信同款手感，滑动即切换，无生硬跳切 |
| 二级页进入/返回 | Navigation Compose 自定义 `slideInHorizontally`(左右滑入) + `slideOutHorizontally` | 替换默认硬切，300ms 左右 |
| 详情/弹层 | 保持现有 `ModalBottomSheet` / `AlertDialog`（已符合微信交互习惯） | 不动 |

关键实现点（来自 CSDN 微信同款整理，§7.3）：
- `pagerState` 与 `NavigationBarItem.selected` 用共享状态联动，`derivedStateOf` 派生当前标题避免多余重组
- `beyondViewportPageCount = 1` 控制屏幕外预加载，避免首页卡顿
- 二级页转场通过 `NavHost` 的 `enterTransition/exitTransition` 注入

## 五、设置页瘦身方案

现状 4 区 + debug 区一张长列表。瘦身方向：

| 分区 | 处理（倾向） | 理由 |
|---|---|---|
| 我的身份 | **迁出** → 移到「我」Tab 独立编辑页 | 不再与 API 配置混在一起 |
| AI API | 保留在设置页，但**默认折叠**（ExpansionTile / 分组卡片展开） | 高级配置不常改，折叠后首屏大幅缩短 |
| 角色作息 | 保留，折叠成一组 | 同上 |
| 互动中心入口 | 迁出 → 已成独立 Tab | 设置页不再重复放 |
| debug 区 | 保留（仅 debug 构建），折叠 | 不影响 release |

> 瘦身后设置页首屏只有「AI API」「角色作息」两个可折叠分组，长度大幅缩减。**分栏是否拆成「双栏」需你定：单栏 + 折叠是倾向方案（风险更低），双栏信息密度高但移动端易局促。**

## 六、记忆与角色卡的成熟方案参考

> 记忆页与角色卡页的「重做」规模较大，本方案给出**方向 + 参考来源**，具体视觉稿待你确认方向后再细化（不凭感觉做）。

### 6.1 记忆页存在的问题
- 顶部同时堆「概览条 + 3 个可视化 chip + 搜索框 + 角色 Tab + 分类 Tab」，层次不分，一眼看不清主次
- 记忆以「平铺条目」为主，缺少「这个角色和我的共同历程」的叙事感

### 6.2 记忆页参考方向（候选）
| 来源 | 可借鉴点 | 对应改造 |
|---|---|---|
| [timeline-memory](https://github.com/unkarelian/timeline-memory)（GitHub，SillyTavern 扩展） | **章节时间轴**：把会话按 AI 归纳的「章节」线性铺开，时序检索 + 智能召回 | 记忆页把「时间轴」从隐藏 chip 提升为**主视图之一**，与列表 Tab 并列 |
| [Smart-Memory](https://github.com/senjinthedragon/Smart-Memory)（GitHub） | 分 profile 注入 + token 预算可视化 + 关系历史单独分层 | 印证「共享/私密分层」方向正确；可补「各角色记忆预算」可视化 |
| 星野「事件簿」 | AI 记录聊天事件，按羁绊组织 | 我们的「共同经历/关系故事」已类似，强化叙事展示即可 |

**记忆页信息架构（候选，待确认）：**
- 顶部只保留：**主视图切换 Tab**（「列表 / 时间轴 / 关系图谱」三选一）+ 搜索框
- 「角色筛选」和「分类筛选」下移为**二级筛选行**（或做成下拉）
- 概览条保留但收窄（4 个统计数字横排一行，不占大块）

### 6.3 角色卡页参考方向（候选）
| 来源 | 可借鉴点 |
|---|---|
| 星野「智能体广场 / 阁楼」 | 角色以**大卡片陈列**，头像+设定摘要一眼看清；「创建」是显性主操作 |
| 筑梦岛「梦中人」 | 「角色管理」作为一级板块，定制入口清晰 |

**角色卡页信息架构（已确认，2026-09-02）：**
- 顶部：**世界书入口卡片**（点击进世界书管理页）
- 第二行：**置顶角色卡** —— 独占一行的大卡片，以**角色立绘**为卡片背景
- 下方：**其他未置顶角色卡** —— 两两一行 / 多列网格排列
- 「新建/导入」保持右下 FAB，作为显性主操作

### 6.4 角色卡页参考 Tavo（用户点名，2026-09-02）

已联网确认 **Tavo**（包名 `app.bitbear.tav`，Bitbear Limited）是一款「AI 角色扮演 / 酒馆」移动端工具。其角色卡页的核心形态可归纳为：

- **角色卡列表 + 「新建/导入」**：支持从**文件导入**（SillyTavern V1/V2 规范，PNG/JSON）与**从 URL 导入**（chub.ai、aicharactercards.com 等社区）；也可从零「新建角色」。
- **角色卡字段**：姓名、性别、开场白、背景故事、性格、说话风格、头像。
- **Tavo 的核心竞争力**（即用户「想要的效果」指向）：长期记忆与上下文延续、角色会**随聊天成长/演变**、预设系统控制文风/POV/防抢话、世界书(Lorebook)动态注入、正则输出控制、群聊、TTS。

> 结论：我们参考 Tavo **角色卡页的管理与导入交互**；而 Tavo 那些「让 AI 说话更像真人」的能力差距，另见 [AI对话效果差距分析.md](./AI对话效果差距分析.md)，不在本 UI 文档展开。

### 6.5 关系图谱（用户给出精确规格，2026-09-02，一字不差）

> 以下为用户的原始规格描述，**不自行增减、不自行简化**：

1. 「我」**默认且强制开启**关系图谱功能。
2. 点开「我」的关系图谱，可以看到「我」与**其他会话角色之间**的事情 —— 前提是**对应会话角色也手动开启了关系图谱功能**。
3. 开启了关系图谱功能的会话角色，会出现在「我」的**下面**。
4. 「我」**置顶且独占一行**；其他会话角色**两两一行**排列。
5. 点开某个会话角色的关系图谱，可以看到其与**其他开启功能会话角色**的关系。

> 数据基础映射（倾向，待确认）：本规格底层可复用现有 `conv_relationship`（会话间关系/好感度）与关系事件 `RelationshipEvent`；「关系图谱开关」需要一个**会话级新开关字段**（默认角色层面关闭、「我」恒开启）。具体数据模型设计在进入实施前单独出索引再动。

## 七、技术调研来源

1. 星野（MiniMax）：底部「我的」+ 个人信息/订阅/设置；「阁楼」创建智能体；「事件簿」记录聊天事件 —— 支撑「我的」Tab 与记忆叙事定位
2. 筑梦岛：「梦中人（角色）/ 小剧场 / 动态」三大板块底部导航 —— 支撑「角色卡是一级板块」定位
3. CSDN《Jetpack Compose：NavigationBar + HorizontalPager 打造微信同款底部导航》—— 底部 Tab + 滑动切换 + 性能优化（`beyondViewportPageCount`）实现路径
4. [FlowTab-CMP](https://github.com/Alims-Repo/FlowTab-CMP)（GitHub）：动画底部导航库（玻璃拟态 / 搜索展开 / 平滑动画）—— 若想要更强动画质感可选，但**倾向不引入第三方库**、用官方 `NavigationBar + Pager` 自研，控制体积与依赖
5. [BottomBars](https://github.com/Shoaibkhalid65/BottomBars)（GitHub）：多种 M3 底部栏样式参考
6. [Smart-Memory](https://github.com/senjinthedragon/Smart-Memory) / [timeline-memory](https://github.com/unkarelian/timeline-memory)：记忆分层 / 时间轴章节范式

## 十、风险与遵守的纪律

- **稳定性优先**：本重构动导航骨架 + 全部一级入口，回归面大。严格逐任务点推进、每点编译 + 真机验证 + 人工审核，不一次性提交大改。
- **数据安全**：本次只改 UI 导航层，不碰数据库 schema / 记忆 / 会话数据；无需迁移。真机验证仍走 `adb install -r` 覆盖安装保全数据，禁用会卸载重建的 `connectedDebugAndroidTest`。
- **决策表述纪律**：本文所有未获你明确表态者均为「倾向/暂定/候选（待确认）」，不出现「已定/淘汰/定案」。
- **代码规范**：改动全部带中文注释，命名遵 camelCase/PascalCase，函数≤30 行，不新增无用文件/依赖。
