# 世界书（Lorebook / World Info）方案

> 状态：**草案（待用户审阅）**
> 依据：交叉验证 SillyTavern World Info、DeepLore、Tavern Studio、Tavo，取公约部分做移动端精简适配。

---

## 一、一句话结论

世界书 = 「**关键词 → 条目**」的动态词典。聊天中扫描到关键词才注入对应条目；没聊到不注入。相比把 `background` 整段塞进 prompt，**省 token、更精准、能承载大世界观**。

---

## 二、定位：独立 + 挂载到"会话"

按用户 2026-09-02 决策：

- **世界书是独立实体**：有自己的管理页（列表 + 新建/编辑/删除条目），不从属于角色卡编辑页。
- **挂载单位是「会话」而非「角色卡」**：世界书挂在某个具体会话上，可**随时挂载 / 卸下 / 切换**。同一张角色卡开的 A、B 两个会话，各挂不同的世界书（符合"角色卡 ≠ 会话角色"）。

> 数据关系：`角色卡(模板) 1:N 会话(实例)`，`世界书 M:N 会话`（一个会话挂一个世界书；一本世界书可被多个会话各自挂载）。第一版简化为**一个会话挂 0 或 1 本世界书**（`null` = 未挂载），多本可后议。

---

## 三、四家交叉验证后的「公约字段」

| 字段 | 类型 | 作用 | 来源 |
|---|---|---|---|
| `keys` | 数组 | **主关键词**，命中即触发 | 四家一致 |
| `secondaryKeys` | 数组（可省） | 副关键词，AND 逻辑收窄误触发 | SillyTavern / DeepLore |
| `logic` | 枚举 | `AND_ANY`(主+任一副) / `AND_ALL`(主+全部副)，默认 AND_ANY | SillyTavern / DeepLore |
| `content` | 文本 | 真正注入的条目内容（**自包含**，不含关键词/标题） | 四家一致 |
| `priority` | 数值 | 越小越先注入；10-20=核心 / 50=标准 / 80-100=边角 | DeepLore |
| `constant` | 布尔 | 恒定注入（"蓝灯"），无条件每次注入 | SillyTavern / NGA |
| `enabled` | 布尔 | 开关 | 四家一致 |

> 暂不引入（后议）：正则关键词、递归激活、cooldown/warmup/probability、AI 语义检索(summary/BM25)。**第一版只做「关键词精确匹配」跑通。**

---

## 四、触发与注入机制（第一版）

```
用户消息命中 keys 任一主关键词
    ↓
（若配 secondaryKeys + logic）需同时满足副关键词逻辑
    ↓
按 priority 升序收集命中条目
    ↓
受 token 预算约束（默认 2000 token，可配范围 500~5000）
    ↓
拼成一段「世界书背景」注入 system prompt
```

- **扫描范围**：最近 N 条消息（第一版 `N = 3`，含用户消息 + 角色回复）。
- **恒定条目**：`constant = true` 无条件每次注入（用于"核心世界观规则"）。
- **不保证输出**：世界书是背景提示，不保证 AI 一定复述条目内容（与 SillyTavern 一致）。

## 五、数据模型（落到 EdenCourt，暂名）

**新增表 1：`world_info_book`（世界书，独立实体）**

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键 |
| `name` | String | 世界书名称 |
| `description` | String | 简介（可选，不注入） |

**新增表 2：`world_info_entry`（条目，挂世界书）**

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键 |
| `bookId` | Long | 外键 → `world_info_book.id` |
| `title` | String | 条目名，仅导航，不注入 |
| `keys` | String | 主关键词，逗号/顿号分隔 |
| `secondaryKeys` | String | 副关键词（可空） |
| `logic` | String | `AND_ANY` / `AND_ALL`，默认 AND_ANY |
| `content` | String | 注入内容 |
| `priority` | Int | 越小越先注入 |
| `constant` | Boolean | 是否恒定注入 |
| `enabled` | Boolean | 开关 |

**改动表：`conversation` 新增一列**

| 列 | 类型 | 说明 |
|---|---|---|
| `worldBookId` | Long? | 挂载的世界书 id，`null` = 未挂载 |

**注入点**：在 [ChatPromptAssembler.kt](../../app/src/main/java/com/bdalxy/edencourt/feature/chat/ChatPromptAssembler.kt) 新增 `buildWorldInfoFragment()`，读会话挂载的世界书 → 扫描命中 → 拼进 [PromptBuilder.build](../../app/src/main/java/com/bdalxy/edencourt/domain/PromptBuilder.kt) 的 system prompt（角色卡人设之后、记忆之前）。

**挂载/卸下**：在**会话角色页面**提供"世界书"入口，可查看当前挂载、挂载/切换/卸下（设为 null）。

## 六、已确认决策（2026-09-02）

1. **独立入口放哪**：世界书管理页入口放在**「角色卡」Tab 顶部**（一张入口卡片）。
2. **一个会话挂几本**：第一版**一个会话最多挂 1 本**（`null` = 未挂载），多本后议。
3. **token 预算默认值**：**默认 2000 token，可配范围 500~5000**（设置页可改）。
4. **角色卡 Tab 布局**：顶部=世界书入口卡片；第二行=置顶角色卡独占一行大卡片（立绘背景）；下方=其他角色卡两两一行/多列网格。
