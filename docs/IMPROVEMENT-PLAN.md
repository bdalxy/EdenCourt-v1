## 1. 全面诊断与分析

### 1.1 诊断方法

- **静态诊断**：审阅 PLAN.md 任务闭环、ROADMAP 蓝图、企划书需求，梳理已落地能力与已知遗留。
- **运行诊断**：K60 真机实测（冷启动 756~779ms、内存 163MB、0 FATAL）+ ADB/数据库核对 + UI 走查。
- **体验诊断**：以「初次接触用户」视角走查全流程（首启→建会话→聊天→记忆→互动）。
- **流程诊断**：评估「开发→验证→推送」闭环与文档/决策可追溯性。

### 1.2 问题清单（带依据与归属）

### 1.3 关键瓶颈与根因

1. **瓶颈一：真人感「三支柱」未立**（P-01/02/03）——产品已具备性格/记忆/主动，但缺「生活时间线、自发动机、关系事件」三个让角色"活起来"的地基。根因：MVP 聚焦"能聊能记住"，未触及"角色有自己的生活节奏"。
2. **瓶颈二：新用户冷启动失败**（P-04）——功能跑得比引导快，入口深、无开场仪式。根因：以"功能可用"而非"体验完整"为验收口径。
3. **瓶颈三：体验可靠性靠"模型自觉"**（P-05/06）——人设/记忆引用均无确定性机制兜底。根因：无本地约束层、检索与触发策略偏简单。
4. **瓶颈四：工程质量缺口**（P-07/08/09）——数据增长性能、自动化回归、发布收尾欠账。根因：单人开发以"功能推进"优先，工程债后置。

## 2. 改进方案设计

> 每个方案给出：解决的问题、核心改进点、实施范围、预期效益、方案变体（可选）。

### 方案 A · 角色时间线生活系统（解决 P-01）
- **核心改进点**：为每个角色建立「生活状态机」——按真实时间线自动切换状态（睡眠/晨起/日常活动/工作学习/社交/休息），状态影响：① 回复时机与语气（深夜被叫醒会困倦）；② 会话列表角色卡片显示「此刻状态」；③ 主动互动时机（不在睡眠窗口硬触发）。数据源：角色卡设定 + 可配置作息表 + 真实时间。
- **实施范围**：新增 `CharacterSchedule` 状态机（实体/配置）+ ChatScreen 状态展示 + 与 T11.7 自动驱动联动（睡眠窗口不串门）。
- **预期效益**：玩家随时打开都知道"TA 在干嘛"——真人感最直接、可感知的提升；为 B/C 提供"生活场景"素材。
- **变体**：A1 轻量（仅状态机+展示，不动对话行为）· A2 完整（状态参与 prompt 与互动调度）。

### 方案 B · 事件驱动自发动机（解决 P-02）
- **核心改进点**：把「闹钟+概率」升级为「事件+动机」——用角色记忆中的「事」（用户提过光羽、一起喝过奶茶、上次约好明天见）作为触发器：满足触发条件（时间/关系/记忆主题）时，以"因某件事而起意"的方式发起互动（例：因记得你昨天说过喜欢奶茶 → 主动来聊）。保留定时窗口兜底，但优先走事件驱动。
- **实施范围**：`InteractionAutoExecutor` 升级（事件候选生成器）+ 记忆主题关联 + 互动开场白注入"因事"。
- **预期效益**：主动行为有因果感、可解释（"因为你提到过…所以我来了"），从"被调度"变"自发想起"。
- **变体**：B1 仅"记忆主题→互动话题"（成本低，已部分具备）· B2 完整事件触发器（含冷却/去重升级）。

### 方案 C · 关系事件系统（解决 P-03）
- **核心改进点**：为「角色-角色」/「角色-用户」关系引入「共同经历事件」——每次互动记录事件（场景/主题/氛围/关键内容），好感度变化附注事件；关系页显示"我们之间发生过的事"（里程碑式叙事：第一次见面→第一次深夜谈心→关系升温）。事件参与 prompt，让对话有"我们经历过"的连续性。
- **实施范围**：`ConversationRelationship` 扩展事件表（或复用 interaction_turn）+ 互动中心「关系故事」区 + PromptBuilder 事件注入。
- **预期效益**：关系从"数值"变"叙事"，陪伴深度显著提升；与记忆系统天然衔接。
- **变体**：C1 仅记录+展示事件时间线 · C2 事件参与对话上下文（完整）。

### 方案 D · 新手上手与功能可发现性（解决 P-04）
- **核心改进点**：① 首次启动引导（2~3 步：你是谁→她们是谁→能做什么）；② 入口重构——互动中心/记忆可视化/自动驱动从二级入口提为「主界面可发现」（会话列表角色卡显示状态、顶栏或首页宫格入口）；③ 空态引导文案（"长按试试"）。
- **实施范围**：`MainActivity`/ConversationList 首启向导 + 入口布局调整 + 各页空态。
- **预期效益**：新用户 3 分钟内建立"这是活在手机上的真人"的心智；功能发现率提升。
- **变体**：D1 仅首启引导 · D2 引导+入口重构（推荐）。

### 方案 E · 人设约束层（解决 P-05，远期候选）
- **核心改进点**：本地小模型（Qwen2.5-1.5B 量化 GGUF + llama.cpp/NNAPI）做人设守门与输出审核（企划书 4.4.3 输出审核），云端回复过审后放行；或退一步做「prompt 强化 + 输出规则校验（正则/关键词拦截跳出人设）」。
- **实施范围**：本地推理接入（大）或 PromptBuilder 强化（小）。
- **预期效益**：人设稳定性硬保证；离线兜底。
- **⚠️ 前置**：先做 1.5B 在 K60 的内存/时延实测（ROADMAP 已注明），不达标不立项。

### 方案 F · 记忆主动引用增强（解决 P-06）
- **核心改进点**：① 检索升级——top-K 提升 + 相关性重排（结合 FTS/时间衰减/情感权重）；② 触发增强——在"合适时机"（用户提到相关主题/开场/深夜）主动引用记忆；③ 提取质量——增加更正确认闭环与脏数据清理工具。
- **实施范围**：`MemorySearchService` + `MemoryRepository` + `PromptBuilder`。
- **预期效益**：记忆"被感知"率提升（命中率目标 ≥80%），强化"它记得我"的核心卖点。

### 方案 G · 性能与工程质量（解决 P-07/08/09）
- **核心改进点**：① 列表分页/懒加载（会话、消息、记忆）；② 流式 UI 节流（delta 合并按帧渲染）；③ 自动化回归集（核心链路：聊天/记忆/互动的 UI 冒烟 + Room 迁移升级测试）；④ 发布收尾（Release v1.0.0 + CHANGELOG 完整）。
- **实施范围**：数据层 + UI 层 + 测试工程 + 发布。
- **预期效益**：千条数据 60fps；任意版本升级 0 崩溃；每次改动回归有据可查。

## 3. 多维度复杂度评估

### 3a. 实施复杂度评估（评分体系）

**量化评分标准**（每维度 1~5 分，5=最高成本/最高风险）：

| 维度 | 权重 | 1 分（低） | 3 分（中） | 5 分（高） |
|---|---|---|---|---|
| 技术难度 | 0.30 | 纯 UI/配置改动，无新依赖 | 涉及状态机/新表/新调度，复用现有模式 | 涉及本地推理/复杂算法/跨层改造 |
| 资源需求 | 0.25 | 仅现有真机+现有依赖 | 需新增少量数据模型/配置 | 需新硬件/大模型/新依赖库 |
| 时间成本 | 0.25 | ≤1 个任务点闭环 | 2~4 个任务点 | ≥5 个任务点或跨多阶段 |
| 潜在风险 | 0.20 | 可完全回滚，无副作用 | 有数据迁移/行为变更风险，可控 | 涉及系统权限/模型效果/兼容性不确定 |

**加权总分 = 技术×0.30 + 资源×0.25 + 时间×0.25 + 风险×0.20**。档位：≤2.0 低 · 2.1~3.2 中 · ≥3.3 高。

| B 自发动机 | 3 | 2 | 3 | 3 | 2.75 | 中 |
| C 关系事件 | 3 | 2 | 3 | 2 | 2.55 | 中 |
| D 可发现性 | 2 | 1 | 2 | 1 | 1.55 | 低 |
| E 人设约束层 | 5 | 4 | 4 | 4 | 4.30 | 高 |
| F 记忆引用 | 3 | 2 | 2 | 2 | 2.35 | 中 |
| G 性能工程 | 3 | 2 | 3 | 2 | 2.55 | 中 |

### 3b. 功能复杂度评估（评分体系）

| 维度 | 1 分（低） | 3 分（中） | 5 分（高） |
|---|---|---|---|
| 功能模块复杂度 | 单一页面/单一数据源 | 多页面+新表+联动 | 跨模块+状态机+调度 |

- **建议插入位置**：方向 B 完成 T11.8 后，开辟「方向 B'：角色活力」阶段（N1→N3），N4 可并行于任何阶段。

### 5.3 与产品战略（"从聊到帮"）一致性

- 本方案不改变 v2.0「从聊到帮」方向，而是**先把"活"做扎实**：角色有生活（A）、有关系叙事（C）、会因事主动（B）——这些是 2.0 设备操作/代理能力前的"角色人格底座"，与 ROADMAP 指导原则 1（先立底座再上应用）一致。

## 6. 实施路径规划

### 6.1 分阶段路线图

```
Phase 0 · 准备与对齐（本轮）
  输入：本方案人工审核通过 + 新增需求（N1~N4）插入 PLAN
  交付：PLAN 任务链更新 · 方案定稿 · 基线 KPI 采集（真人感自评/功能发现率/记忆命中率抽样）

Phase 1 · P0 第一支柱（真人感地基）
  D 可发现性（首启引导+入口重构）→ A 时间线生活（状态机+展示+调度联动）→ C 关系事件（事件表+关系故事）
  里程碑 M1：新用户 3 分钟建立心智；角色卡片可见"此刻状态"；关系页可见"共同经历"

Phase 2 · P0 第二支柱（主动有灵魂）
  B 自发动机（事件触发优先 + 定时窗口兜底）→ 与 T11.8 互动信息不对等协同
  里程碑 M2：主动互动"因事而起"占比 ≥60%；自动互动开场白可解释

Phase 3 · P1 体验增益与工程保底（随版本并行）
  F 记忆引用增强 → G 性能工程（分页/节流/回归集）→ 发布收尾（Release v1.0.0）
  里程碑 M3：记忆命中率 ≥80%；千条数据 60fps；核心链路回归集可用

Phase 4 · P2 远期候选（另行立项）
  E 人设约束层：先跑 1.5B 真机容量测算 → 达标再立项，不达标维持 prompt 强化
```

### 6.2 关键里程碑

| 里程碑 | 内容 | 完成标志（可验证） |
|---|---|---|
| M0 | 方案评审通过 + N1~N4 入 PLAN | 看板更新 · 用户拍板 |
| M1 | 可发现性 + 时间线生活 + 关系事件 | 真机走查达标（见 §8 KPI） |
| M2 | 自发动机 | 主动互动因果占比≥60% |
| M3 | 记忆增强 + 性能 + 发布 | 命中率/帧率/Release 达标 |

### 6.3 责任分配与进度跟踪

- **角色**：开发者（用户）= 产品决策/终审/真机复核；AI 助手（Trae）= 任务拆解/实现/自测/推送。
- **机制**：沿用用户规则——每个任务点「操作→实现→编译+真机自测→更新 PLAN→交人工审核→推送 GitHub」；一次只做一个任务点。
- **跟踪载体**：PLAN.md（唯一看板）+ 本方案文档（改进进度表）+ 会话记忆（自动落盘）。

### 6.4 质量监控标准

- 每任务点：编译通过 + K60 真机验证（提供操作流程+合格标准）方可标完成（企划书 3.2.1）。
- 每阶段：不破坏既有聊天/记忆/互动链路（回归走查）。
- Room 迁移：schema 与索引严格一致（历史血泪教训固化）。
- 每版本推送前：关键链路冒烟（聊天流式/记忆注入/互动执行）。

## 7. 资源分配方案

### 7.1 资源盘点

| 资源 | 现状 | 缺口 |
|---|---|---|
| 人力 | 1 名开发者 + AI 助手（Trae 多 agent） | 无（单人项目） |
| 硬件 | 红米 K60（16+512，真机）、荣耀 Win RT（16+1T） | E 方案需真机容量测算资源 |
| 预算 | DeepSeek API 自备密钥 | 维持现状；E 方案评估期需小模型下载/推理资源 |
| 时间 | 按任务点闭环，不卡死（企划书 6.15 ②） | 无硬性排期 |

### 7.2 配置计划（对应 §4.3 占比）

- **AI 助手侧**：70% 算力投入优选组合；D/F（低复杂度）用轻量 agent 快速闭环；A/B/C（核心）用完整「规划→实现→自测→审核」链路；G 随版本穿插。
- **开发者侧**：30% 精力用于：方案/优先级拍板、真机复核、人工审核门槛、梯子/推送协作。
- **硬件/预算**：维持现有 1 真机 + API；E 方案立项前单独做容量评估（内存/时延/模型下载体积）。

### 7.3 效率指标与动态调整

| 指标 | 目标 | 调整触发 |
|---|---|---|
| 任务点闭环率（编译+真机通过） | 100% | <100% 时停下排查，不放行 |
| 单任务点返工率 | ≤20% | 返工偏高→缩小任务粒度/补诊断 |
| 用户复核通过率 | 阶段级 100% | 未通过→回炉重做 |
| 推送成功率（梯子协作） | 100% | 失败→重试临时代理，不改全局 config |
| 资源超支 | 单项占比超 5% | 重新排优先级，砍低杠杆项 |

## 8. 效果评估与持续优化

### 8.1 量化 KPI 体系（与目标挂钩）

| 维度 | 指标 | 基线 | 目标（M3 验收） | 度量方式 |
|---|---|---|---|---|
| 真人感 | 八维自评总分 | ~75% | **≥85%** | 前序评价表重测 |
| 生活感 | 角色"此刻状态"可见 | 无 | 每个角色卡片常显状态 | UI 走查 |
| 自发动机 | 主动互动"因事而起"占比 | ~0% | **≥60%** | 互动记录抽样标注 |
| 关系叙事 | 每对关系已记录事件数 | 0 | ≥3 件且关系页可见 | 数据库统计+UI 走查 |
| 上手 | 新手完成首启引导率 | 无引导 | **≥90%** | 首启引导完成埋点 |
| 记忆 | 主动引用命中率（"它记得我"） | 抽样 <50% | **≥80%** | 会话抽查标注 |
| 性能 | 千条列表滚动帧率 | 未测 | **≥60fps** | 真机 profile |
| 性能 | 冷启动/内存 | 756ms/163MB | 不劣化 | 复测基线 |
| 工程 | 任意版本升级 | 0 崩溃（历史） | 保持 0 崩溃 | 升级回归集 |
| 质量 | 核心链路回归 | 人工走查 | 回归集覆盖 | 自动化冒烟 |

### 8.2 评估节奏

- **每任务点**：编译+真机自测（现有流程）。
- **每阶段（M1/M2/M3）**：对照上表 KPI 采集一次，写入 PLAN 阶段收尾 + 本方案 §6.1 进度表。
- **每版本推送前**：关键链路冒烟 + 更新记录回填。

### 8.3 持续优化闭环

```
实施 → 真机验证 → KPI 采集 → 与基线/目标对比
   ↓（不达标）                                ↓（达标）
  回炉/缩小任务粒度 ←——————————  冻结该阶段，进入下一阶段
                ↓
        每 3~5 个任务点回看本方案：目标是否仍对齐？新增需求是否要插入？
```

- **前瞻机制**：每阶段结束由 AI 助手做「下一阶段输入诊断」（复用 §1.1 方法），防止方向漂移。
- **闭环管理**：本方案文档 + PLAN.md + 会话记忆三处保持一致（继承 ROADMAP §0 纪律），任何一处更新须同步另两处。
