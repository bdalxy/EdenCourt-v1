# 咨询 DeepSeek 专家模式：角色间互动的身份与称呼设计

> 用途：这是 EdenCourt（AI 角色聊天应用）的「角色间互动」功能遇到的产品/技术设计难题，
> 请你以产品+LLM 应用专家的视角，帮忙评估方案、给出建议。

***

## 一、项目背景（帮助你理解）

- EdenCourt 是一款 AI 角色聊天应用：用户与多个「角色卡」（人设设定，如"小夏"）建会话聊天。
- 产品语义（已定稿）：**一个会话 = 一个独立的"真人个体"**。同一张角色卡可以开多个会话，
  相当于同一个"人格"的多个平行分身（如两个"小夏"会话），它们的经历各自独立。
- 已实现「角色间互动」：两个会话个体 A、B 可以发起一场**双向对话**（A→B→A→…），
  由 LLM 逐轮生成台词，每轮只给当前说话者注入「他自己的记忆」+「双方已说出口的对白历史」，
  保证隐私隔离；最多 6 句（约 2\~3 个来回），每句 ≤60 字。

## 二、问题第一部分：同卡会话互动时的「身份/称呼」镜像

### 现象

当 A、B 绑定**同一张角色卡**时（两个"小夏"），互动对话出现"克隆人镜像"：
两个角色都用角色卡人设的自称（如角色卡人设自称"学姐"），并且**互相也称呼对方"学姐"**。
对话看起来像是同一个人在跟自己说话，用户观感：三次元里不可能存在，很假、很奇怪。

### 根因

- 互动时每轮给说话者注入的 `system` 是**同一张角色卡的完整 persona**（含"学姐"自称）。
- prompt 里只告诉模型"你是小夏"，没把 A、B 两个个体区分开。
- 结果：两个会话的 LLM 都认为"我是学姐"，导致镜像。

### 我们的候选方案

| 方案        | 做法                                                                                             | 优点      | 缺点                     |
| --------- | ---------------------------------------------------------------------------------------------- | ------- | ---------------------- |
| A. 强制区分身份 | 互动时给每个会话一个**唯一身份名**（用户给会话设置的备注优先；无备注时用「角色名·会话序号」如"小夏·会话2"），prompt 明确"你是 X、对方是 Y"，让它们用各自身份自称/互称 | 可靠，不再镜像 | 无备注时"小夏·会话2"这种序号进对话略机械 |
| B. 提示自然区分 | 仍共用角色名，但 prompt 提示"你们是不同个体、避免用相同称呼互相称呼"，让 LLM 自行形成不同叫法                                         | 简单，对话自然 | LLM 可能仍镜像，不保证          |
| C. 禁止同卡互动 | 同角色卡会话之间不允许互动，只能不同角色卡之间互动                                                                      | 从根源避免镜像 | 违背"同卡也支持"的已定稿语义，减少互动场景 |

### 想请教的问题

1. 从产品语义和用户观感看，A / B / C 哪个更优？为什么？
2. 有没有更好的**第 4 种方案**？例如：
   - 互动开场时让 LLM 为双方**自然协商/生成一个互相称呼的方式**（而不强制指定身份名）？
   - 或者把"会话身份"与"人设性格"分离：同卡互动时只注入性格、不注入"名字/称呼"，让双方在对话中自然确立各自叫法？
   - 或者同卡互动时干脆用"双胞胎/镜像"设定把它做成**有意的剧情**，而不是缺陷？
3. 如果选方案 A：无备注时，用什么**身份名最自然**（序号？日期？短码？还是别的），既能让 LLM 区分彼此、又不显得机械？

## 三、问题第二部分：互动 UI 上「会话显示名」的区分

### 现象

会话列表/互动列表/互动选择器里，同一角色卡的多个会话都显示同名（两个"小夏"），用户分不清该选哪个。

### 我们已定的规则（已实现）

- 有**会话备注**（用户长按会话可设置，如"小夏A"）→ 优先显示备注；
- 无备注 → 显示角色名；
- 同一角色卡有多个会话个体且无备注 → 角色名后附**短码尾4位**兜底区分（如"小夏·CB96"）。

### 想请教的问题

1. 这个"备注优先、短码兜底"的规则合理吗？短码是否仍偏机械？有没有更自然、但又能保证唯一可辨的兜底标识？

总体判断：**不建议 B 或 C，建议以 A 为底座，但把“身份标识”和“对白中的称呼”解耦，做一个 A+ 方案。**\

## 一、同卡会话互动时的身份/称呼镜像

### 1. A / B / C 哪个更优？

结论：**A 方向正确，但需要优化；B 不可靠；C 违背已定稿语义。**

- **C 禁止同卡互动**：\
  直接违背“同一张角色卡可开多个会话，同一人格的平行分身”的产品语义。同卡互动其实是很有剧情潜力的场景，例如“两个小夏相遇”“不同世界线的自己对话”。直接禁止会减少互动场景，不建议。
- **B 只提示自然区分**：\
  太依赖 LLM 自觉。角色卡 persona 中的自称先验很强，尤其当 persona 明确写有“你是学姐”“你自称学姐”时，模型很容易继续镜像。\
  即便加入“你们是不同个体、避免用相同称呼互相称呼”，仍可能输出“学姐对学姐说……”，不可控。
- **A 强制区分身份**：\
  这是唯一能稳定解决镜像问题的方向。\
  但你说得对，直接让“小夏·会话2”进入对白很机械，容易让用户出戏。\
  所以更好的做法不是抛弃 A，而是改造它：**把“身份名”作为系统内部标识，不要求角色在台词里逐字使用它。**

***

### 2. 更好的第 4 种方案：身份层与人格层分离 + 自然称呼约束

我建议把它称为：

> **D：互动身份卡 + 人格层复用 + 对白称呼自然化**

具体拆成四步。

#### 第一步：互动时创建临时“互动身份”

每个参与互动的会话个体拥有一个临时身份标识：

- 有会话备注 → 用备注，例如“小夏A”。
- 无备注 → 用稳定内部 ID，例如“小夏·CB96”。

但这个身份标识主要用于：

- system prompt 里区分双方；
- UI 列表里区分会话；
- 日志、调试、状态管理。

**不要求角色在台词里直接说“我是小夏·CB96”。**

#### 第二步：人格层与身份层分离

同卡互动时，不要把角色卡的完整 persona 原样注入，而是做一次“身份改写”。

例如原 persona 里有：

> “你是小夏，自称学姐，性格温柔……”

互动时改写为：

> “你共享小夏的基础人格：温柔、学姐气质。\
> 但这次互动中，你是会话 A 中的小夏，对面是会话 B 中的另一个小夏。\
> 你们是不同个体。\
> 自称统一用‘我’；\
> 称呼对方时，使用‘你’‘另一个小夏’‘对面的小夏’‘她’等自然说法。\
> 不要称呼对方为‘学姐’，也不要把‘学姐’当作你们两个共同的自称。”

这样做的关键是：**保留性格，但解绑固定自称和名字对双方同时生效。**

#### 第三步：在 prompt 中加入硬约束和 few-shot

可以在互动 system prompt 中增加类似：

```text
[身份规则]
- 你是：会话A的小夏，内部标识为“小夏·A”。
- 对方是：会话B的小夏，内部标识为“小夏·B”。
- 你们共享同一套基础人格，但是两个独立个体。
- 自称：只用“我”。
- 称呼对方：优先使用“你”“另一个小夏”“对面的小夏”“她”。
- 禁止：双方互相使用同一个人设固定自称，例如互相叫“学姐”。
```

再给一个 few-shot 示例：

```text
示例：
A：你是另一个我？
B：嗯，我是另一个小夏。你看起来和我一样，但又不完全一样。
A：真奇怪，我从来没想过会遇见“我”。
B：我也一样。不过现在先别管这个了，你为什么会在这里？
```

这样模型会明确知道“两个小夏”是可以自然对话的，而不是镜像复读。

#### 第四步：可选“镜像/双生剧情”作为显式模式

如果你愿意，可以把“同卡互动”包装成一种特殊剧情模式，例如：

- 默认模式：自然区分，两个小夏像同名双胞胎或不同世界线的自己。
- 镜像模式：用户可以选择让她们故意演“镜像”“分身”“复制体”的剧情。

但我不建议把镜像当作默认结果。\
它更适合作为用户可选的彩蛋，而不是缺陷的被动呈现。

***

### 3. 如果选 A，无备注时用什么身份名最自然？

建议把“内部身份名”和“对白称呼”分开。

#### 内部身份名

用于 system、UI、日志，不进入角色对白。

推荐：

- **短码尾 4 位**：稳定、唯一、中性。
- 或者“角色名·序号”，例如“小夏·2”。

序号和短码都可以，但**不要直接进入对白**。

如果必须进入对白，可以用自然转写：

- “另一个小夏”
- “对面的小夏”
- “这边的我”

而不是：

- “小夏·会话2”
- “小夏·CB96”

#### 对白中的称呼

由模型根据 prompt 自行选择自然说法。

例如：

```text
你：我这是在做梦吗？
对方：不是梦，我是另一个小夏。
你：原来这世上真的有另一个我。
```

这比“小夏·会话2说……”自然得多。

#### 为什么不用日期？

日期不稳定，且同一角色卡可能同一天创建多个会话；\
而且日期容易暴露创建时间，用户不一定喜欢。

短码虽然机械，但它是兜底标识，目标是“唯一可辨”，不是“自然”。\
自然的责任应该交给用户备注，或者未来的自动昵称功能。

## 二、互动 UI 上「会话显示名」的区分

### 1. “备注优先、短码兜底”是否合理？

合理。

- **备注优先**：用户自己设置的名称最有意义，也最符合用户心智。
- **短码兜底**：唯一、稳定、中性，不会像序号那样直接暴露创建顺序，也不会像日期那样暴露隐私。

短码确实机械，但这是兜底方案的合理代价。\
**不要试图让兜底标识变得“自然”。**\
兜底标识的核心价值是：

- 唯一可辨；
- 稳定；
- 不打扰。

如果追求自然，应该引导用户设置备注，而不是让系统猜测。

***

### 2. 如何降低短码的机械感？

可以在 UI 上做三件事，而不是换掉短码。

#### ① 短码只用于列表和选择器，不进入对话

互动过程中，对白里绝不出现“小夏·CB96”。\
短码只作为列表里的辅助标识。

#### ② 在互动选择器中增加上下文信息

同卡多会话时，不要只显示：

```text
小夏·CB96
小夏·3F2A
```

而是显示：

```text
小夏·CB96 · 3分钟前 · 最后一句：“今天去海边吗？”
小夏·3F2A · 昨天 · 最后一句：“我最近在学做甜点。”
```

这样用户可以通过最近互动内容区分两个会话，短码只作为稳定 ID 存在。

#### ③ 支持快捷备注或颜色/emoji 标记

例如用户长按会话后，除了备注，还可以给会话加颜色标签或 emoji：

```text
小夏 🔵
小夏 🟣
```

这比短码更直观。\
但颜色/emoji 数量有限，不能完全替代短码，适合作为辅助。

***

## 最终建议

1. **同卡互动不要禁，也不要只靠提示。**\
   采用 A 的确定性思路，但把“身份标识”和“对白称呼”解耦。
2. **实现“互动身份层”**：\
   备注优先；无备注用短码作为内部 ID；prompt 中明确“你是 X，对方是 Y”，但要求模型用自然方式称呼彼此。
3. **对 persona 做一次互动期改写**：\
   保留性格，但解绑固定自称/名字对双方同时生效。
4. **UI 上保留短码兜底**，同时通过最近消息、时间、颜色/emoji 等辅助信息降低机械感。
5. **可选做“镜像/双生”作为显式模式**，但不作为默认结果。

这套方案既可靠，又不牺牲同卡互动的剧情潜力，同时兼顾了用户观感和工程可控性。
