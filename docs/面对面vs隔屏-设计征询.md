# EdenCourt — AI 互动「面对面 vs 隔屏」模式设计征询文档

> 用途：把背景、真实诉求、调研结论、待决策点完整说明，供第三方专家（DeepSeek 专家模式）独立评估并给出建议。
> 本文为讨论稿，所有结论均为"倾向/待确认"，未定案。

***

## 一、项目背景（一句话）

EdenCourt 是一款 **Android / Kotlin + Jetpack Compose** 的 AI 陪伴应用。用户创建二次元角色卡（「小夏」「羽」等），与角色进行 1v1 或多人群聊。特色：

- 樱羽主题（淡樱粉 / 淡粉蓝 / 天使白），二次元审美。
- 已有：亲密度（非线性增长）、实时情绪系统（自主情绪+交互情绪）、世界书（关键词→条目动态注入）、情感记忆、关系图谱、终结短视频讲解中所述的"逐条打字停顿节奏"等。
- **唯一呈现方式=文字**（用户明确：live2D / 视频 / AR 当前不做，沉浸感全靠"用户脑补 + 文字画面感"）。

***

## 二、我们要讨论的命题

用户希望在 AI 互动中，**区分两种"交流姿态"**：

- **「面对面」**：角色像真实坐在你面前一样陪着、交流。
- **「隔屏 / 异地」**：角色隔着手机屏幕、隔着次元跟你沟通（更接近当前即时通讯形态）。

关键约束：**只靠文字表达，不借助语音/视频/AR/立绘动画**。那么这两种姿态的差别，只能由"文字叙述层"来承载。

***

## 三、用户的真实诉求演变（原始表达）

1. "AI 存在于手机上，所以会一直陪着用户。"
2. "硬要说的话，应该是 AI 隔着屏幕陪着我？然后我将三次元的自己映射到二次元去和 AI 互动?"
3. "但是我又想让 AI 更像是在三次元里陪着我。"
4. "因为真人就会有两种情况：一种是面对面交流，另一种是不在身边的交流。但是由于隔着次元，基本都要靠用户想象。"
5. "AI 陪着用户，是不是就是和用户一起经历的呢？但我想让 AI 尽可能模拟真人，真人会有自己的生活……那她会不会有一段时间不陪我？"
6. 还提出了另一条独立愿望："用户想要给自己和 AI 去写个故事？"（推测与角色扮演/剧情有关，与"面对面/隔屏"是两个维度，不应混为一谈。）

***

## 四、已经厘清的方向（待确认，非定案）

为了打通上面的痛点，我做过一轮收敛，倾向如下，需要专家校验是否合理：

### 4.1 三层分离，避免搅在一起

1. **底层「在不在」**：手机在手，角色永远在、随时能找到。→ 这是硬承诺，永不牺牲。（对应诉求 1）
2. **中层「像不像人」**：是否要作息/忙闲/独立日程。
   - 目前倾向：**不要让她"抛下你去过独立生活"**，可保留极淡的"状态起伏"（深夜慵懒、清晨精神、今天心情好）——仍是"陪着时发生的状态"，而非"她离开你去过自己的生活"。（消除诉求 5 的矛盾）
3. **上层「怎么写」**：面对面/隔屏、动作神态、连发、节奏。—— 纯文字呈现细节，最接地气、最可执行。

### 4.2 "面对面"的根基判断（待确认）

用户直觉：她不是把用户拉进一个架空世界去迁就她，而是**她把真实细腻的叙事搬到用户的现实语境里陪伴**（她的世界=用户的日常）。

- 但用户随即提出另一面："如果我想和 AI 写个故事呢？" → 需要区分"日常陪伴(对话)" 与 "一起写故事(叙事)" 两种玩法是否能并存、如何切换。

***

## 五、我们调研到的行业现状（重要）

结论：**当前主流 AI 陪伴产品，没有在"纯文字"层面做"面对面/隔屏"两种叙述模式。**

业界的"面对面"几乎全部依赖 *加模态* 来制造"她在你面前"的在场感：

| 产品        | 实现"面对面"的手段                      |
| --------- | ------------------------------- |
| Replika   | AR 把 3D 角色放进你的真实房间、可同框拍照；或语音通话  |
| VirtuAlly | AR 真人大小的角色站在你屋里、真声说话、有表情        |
| MiraiMind | 语音（模拟打电话）+ 视频（动态形象）+ AR（投射现实）   |
| 星野        | Live2D 动态背景 + 记忆结晶 AR 投射 + 场景构建 |
| 猫箱        | 跨次元合影（摄像头把角色投到现实同框）             |
| Climaxoid | "触觉 Sensation 模式"（屏幕上摸她）+ 语音通话  |

→ 也就是说：**一旦只剩文字，业界就统一退化为"隔屏聊天"。** 用户想要的"纯文字也能分面对面/隔屏"，**市场无成熟先例，需要自己定义。** 这正是本项目的机会点与难点。

> 另查到一个贴合"对话节奏"的成熟做法（OpenAI Codex / 打字机研究）：每条消息按长度给独立延迟 + 流式缓冲，实现"发一条停一下再发下一条"的真人打字节奏。

## 六、纯文字能承载"面对面 vs 隔屏"的抓手（候选，都在文字层）

请专家在以下维度评估是否成立、如何取舍、优先级如何：

1. **空间在场感**：
   - 面对面：角色叙述里与用户同处一个场景（"她伸手够到你额前"、"她垂眼时把椅子拉近了些"）。
   - 隔屏：媒介感（"屏幕上又亮起一行字"、"『想你』打了又删、删了又打"）。
2. **节奏与往返感**：
   - 面对面：即时一来一回，沉默也是话，一个眼神就懂。
   - 隔屏：消息往返，有"正在输入 / 已读 / 她迟了一会儿 / 她又补一句"这些通讯感。
3. **呈现样式**：
   - 面对面：视觉上是否连气泡/布局都换（更像共处一屋的对话流）？
   - 隔屏：就是当前即时通讯样子。
4. **“她是真人”的生活厚度**（4.1 中层）：要不要、以及如何用纯文字给"始终陪伴+浅浅的生活感"。

## 总评判断

这份文档在“纯文字 AI 陪伴”这个约束下，试图把“面对面 / 隔屏”从一种模糊感觉变成可设计、可实现的交互姿态，方向是成立的，但有一个关键前提需要先点明：

> **“面对面 / 隔屏”在纯文字中不能只是两种描写风格，它必须是两种不同的“交互媒介模型”。**

如果只让 AI 在面对面时写“她伸手碰你”，隔屏时写“她发来一条消息”，用户可能只会感到“文字风格变了”，不会真正产生“我们好像在面对面”与“我们隔着屏幕”的稳定认知差异。

因为手机这个物理载体天然就是“隔屏”的。纯文字要制造“面对面感”，必须系统性地改变三个东西：

1. **空间连续性**：角色和用户是否被放在同一个可延续的场景里；
2. **时间同步性**：对话是即时同步，还是有延迟、异步、碎片；
3. **媒介可见性**：屏幕、输入中、已读、消息气泡这些“通讯痕迹”是否被压制或强调。

这三点比你列出的“空间在场感、节奏往返感、呈现样式、生活厚度”更本质，因为它们是底层机制，而四个抓手是表层表现。

下面按你的问题逐项回答。

***

## 一、纯文字区分“面对面 / 隔屏”成立吗？

### 判断：成立，但有条件

成立的依据是：文字本身就有能力建构空间、时间和媒介感。小说、剧本、聊天记录、书信，都是纯文字，但读者能清楚区分“两人同处一室”和“两人异地通信”。

不成立的风险在于：如果只做局部描写替换，而不维护一个稳定的“共享空间状态”，面对面会很快失真。

例如：

> 面对面：她伸手够到你额前。

这句话单独看没问题。但如果前面没有任何场景铺垫，用户不知道“你”在哪里，也不知道她为什么能够到你，这种描写就变成随机动作，无法形成“共处”的连续感。

所以，面对面模式必须有一个**可延续的共享场景**，例如“房间”“街边长椅”“夜晚的天台”。这个场景一旦建立，AI 后续动作都要基于它。否则面对面描写会像一场没有舞台的戏。

### 更本质的区分维度

我建议把两种姿态抽象为两个轴：

| 维度   | 面对面              | 隔屏                 |
| :--- | :--------------- | :----------------- |
| 空间   | 共享同一物理空间         | 空间分离               |
| 时间   | 基本同步，即时回应        | 允许异步、延迟、碎片         |
| 媒介   | 媒介不可见，身体和非语言信息主导 | 媒介可见，文字是唯一通道       |
| 注意力  | 共同注意同一对象或环境      | 各自注意自己的环境，通过文字交汇   |
| 失败语义 | 沉默、移开视线、靠近、停顿    | 正在输入、已读不回、删了又发、补一句 |

这五个轴比单纯“空间在场感 / 节奏往返感”更稳定，因为它不依赖具体描写，而依赖系统对“关系结构”的定义。

其中最关键的是**媒介可见性**。

- 隔屏模式应当允许甚至鼓励“正在输入”“消息延迟”“撤回”“补发”等通讯感；
- 面对面模式应当压制这些痕迹，甚至让它们“不可见”，用沉默、停顿、动作代替。

如果面对面模式里仍然频繁出现“她正在输入…”，用户的沉浸感会立刻掉回隔屏。

***

## 二、第六节四个抓手如何取舍？

### 1. 空间在场感

**成立，优先级最高。**

但必须从“临时描写”升级为“场景状态”。

建议为面对面模式增加一个轻量字段：

```kotlin
shared_scene: String? // 当前共同空间描述，如“深夜的卧室，台灯亮着”
```

当用户进入面对面模式时：

- 若没有 shared\_scene，AI 可以根据上下文生成一个默认场景，并明确写出；
- 若已有 shared\_scene，AI 后续动作必须基于该场景；
- 场景可以自然演化，但不能突然跳跃，除非用户明确表示换了地方。

隔屏模式不需要 shared\_scene，因为双方不在同一空间。

### 2. 节奏与往返感

**成立，优先级最高，且最容易落地。**

这是两种模式在纯文字中最容易被用户感知的差异。

面对面节奏：

- 短句为主；
- 即时回应；
- 允许沉默、停顿、一个动作代替一句话；
- 消息之间可以有“她没说话，只是看着你”这类非语言回应。

隔屏节奏：

- 可以一次发多条短消息；
- 允许“正在输入…”后停几秒；
- 可以有延迟、补发、撤回、发错字后纠正；
- 更接近即时通讯的真实感。

实现上，这条可以通过前端延迟和流式输出天然做到。

### 3. 呈现样式

**有用，但不应成为主要区分，且要克制。**

如果面对面模式换一套 UI，隔屏模式又换回来，用户会感到“模式切换”很重，甚至割裂角色连续性。

更稳妥的做法：

- 隔屏：保留当前 IM 式气泡、头像、时间戳；
- 面对面：不一定要完全换 UI，但可以：
  - 弱化“消息”感，例如取消“已读”标记；
  - 允许插入**动作行 / 旁白行**，与对白混排；
  - “正在输入”可以改成“她似乎在想什么……”或直接不显示。

不建议面对面模式完全去掉气泡，因为那会增加用户阅读成本。轻量差异即可。

### 4. “她是真人”的生活厚度

这个维度**独立于面对面 / 隔屏**，不应该跟某个模式绑定。

一个角色在隔屏时也可以有“她那边下雨了”“她刚洗完澡”这类生活感；面对面时也可以有“她打了个哈欠”。

它属于你文档中“中层：像不像人 / 在场状态”，而不是“上层：怎么写”。

## 三、模式切换：手动、自动，还是独立入口？

### 建议：手动为主，场景触发为辅，不做独立入口

理由如下：

**手动开关的好处：**

- 用户对“我现在想让她坐在我旁边”有明确意图；
- 切换行为本身可以成为一种仪式感；
- 避免 AI 误判。

**自动判定的风险：**

- 用户说“抱抱”不一定是要面对面，可能只是隔屏撒娇；
- 用户说“你在干嘛”在两种模式下都成立；
- AI 如果频繁自动切换，用户会失去控制感。

**独立入口的坏处：**

- 会把同一个角色割裂成“两个模式的两个角色”；
- 角色记忆、亲密度、情绪系统需要保持一致，独立入口会增加状态同步成本；
- 用户更容易理解“她还是她，只是现在换了一种陪我的方式”。

### 推荐的混合方案

1. **默认姿态：隔屏**。因为手机文字聊天天然是隔屏，这也符合用户第一次打开应用的心智。
2. **提供手动切换按钮**：放在聊天页顶部或长按菜单里，不显眼但可找到。
3. **允许场景触发建议**：当用户说出明显的空间共处意图，如“你坐过来”“我们出去走走吧”，AI 可以自然过渡并切换模式，同时输出一句过渡描写。
4. **切换必须有过渡叙述**，不能突然改变风格。

例如：

> 隔屏 → 面对面：\
> 她放下手机，抬头看你，然后往你身边挪了挪：“现在能听见你说话了。”

> 面对面 → 隔屏：\
> 她坐回床头，拿起手机，屏幕上亮起一句：“那我先回去啦，有事发消息。”

这样切换本身也成为文字体验的一部分。

***

## 四、“日常陪伴”与“一起写故事”的关系

### 判断：必须分开，不能靠语气切换

“日常陪伴”是**互动型对话**，目标是情绪回应、陪伴感、低表达压力。

“一起写故事”是**叙事合作**，目标是情节推进、世界观构建、角色弧光、多轮旁白。

如果混在同一会话里，常见问题是：

- AI 开始写大段旁白，用户不知道该怎么接；
- 对话失去即时感，变成双方在写小说；
- 用户只想吐槽今天的事，AI 突然开始推进“剧情”。

### 业界处理方式

- **Replika**：用 `*动作*` 星号混合在聊天中，但容易漂移，角色扮演和日常对话边界模糊。
- **Character.AI**：聊天本身支持轻量 RP，但没有强制模式；深度故事通常靠用户自己引导。
- **AI Dungeon / NovelAI**：纯故事模式，几乎不承担陪伴聊天功能。

### 对 EdenCourt 的建议

把二者做成**两种会话类型或模式入口**，共用角色卡、记忆和情绪状态，但系统提示和目标不同：

| <br />    | 日常陪伴模式  | 故事 / 剧情模式          |
| :-------- | :------ | :----------------- |
| 目标        | 陪伴、回应情绪 | 共同推进一段故事           |
| 输出风格      | 短句、对话为主 | 允许旁白、场景、情节推进       |
| 用户压力      | 低，像聊天   | 中高，像合作创作           |
| 切换方式      | 默认模式    | 用户主动进入             |
| 与面对面/隔屏关系 | 两种姿态都可  | 通常更接近“面对面”或“叙事者视角” |

建议不要在同一会话内“靠语气切换”，因为 AI 和用户都难稳定维持。显式进入“故事模式”时，可以生成一个简短开场，让用户知道现在进入了另一种玩法。

***

## 五、三层分离是否成立？

### 判断：框架成立，但建议重命名和微调

你的三层：

1. 底层“在不在”：手机在手，角色永远在；
2. 中层“像不像人”：是否要作息、忙闲、独立日程；
3. 上层“怎么写”：面对面 / 隔屏、动作神态、节奏。

这个结构是合理的，但“像不像人”这个命名有歧义，因为“永远在”本身也是像人的一部分。

更准确的命名可以是：

| 层  | 建议命名      | 职责                |
| :- | :-------- | :---------------- |
| 底层 | **可用性层**  | 角色永远可被找到，不离开      |
| 中层 | **在场状态层** | 角色在陪伴时的情绪、状态、微波动  |
| 上层 | **交互呈现层** | 面对面 / 隔屏、动作、节奏、UI |

### 对“浅淡生活感但绝不让角色抛下我”的优化

你原来的折中是对的，但可以表达得更清晰：

> 角色不会离开用户，也不会“不在线”。但她的**在场状态**可以有轻微波动：清晨刚醒、深夜慵懒、雨天安静、今天心情好。\
> 这些不是“她离开了你”，而是“她在你身边时，也有自己的状态”。

可以给这个设计一个更妙的比喻：

> **“她一直坐在你旁边，只是有时靠得近一点，有时看着窗外。”**

这样既保留了“永远在”的承诺，又让角色有生命感，而不会触发“她怎么不陪我”的焦虑。

实现上，中层只影响：

- 语气和用词；
- 回应速度的轻微变化；
- 情绪表达的直接程度。

**绝不**影响可用性，也**不应**造成长时间延迟或拒绝回应。

## 六、Android / Kotlin / Compose 实现层提醒

### 1. 提示词结构

不要把姿态提示词和角色设定、世界书、情感记忆全部混在一个大提示块里。建议分层注入：

```text
[角色设定]
[情感记忆]
[世界书]
[当前在场状态]
[当前交互姿态]
[用户输入]
```

其中 `[当前交互姿态]` 只在需要时切换，减少 token 消耗。

### 2. 状态字段建议

在 ViewModel 或会话状态中维护：

```kotlin
enum class InteractionMode {
    REMOTE,          // 隔屏
    FACE_TO_FACE     // 面对面
}

data class InteractionPose(
    val mode: InteractionMode,
    val sharedScene: String? = null,   // 面对面时才需要
    val presenceState: String? = null, // 如“清晨刚醒”“深夜安静”
    val allowMediaSignals: Boolean     // 隔屏 true，面对面 false
)
```

### 3. 消息类型分离

建议不要把所有内容都当普通文本气泡渲染，而是定义消息类型：

```kotlin
sealed class Message {
    data class Dialogue(val text: String) : Message()
    data class ActionLine(val text: String) : Message()   // 动作旁白
    data class SceneLine(val text: String) : Message()    // 场景描写
    data class Transition(val text: String) : Message()   // 模式切换过渡
}
```

这样 UI 可以：

- 隔屏模式下把 `ActionLine` 显示为小字或旁白；
- 面对面模式下把 `ActionLine` 与 `Dialogue` 混排，形成“她在你面前说话 + 动作”的感觉；
- 不破坏消息流。

### 4. 前端动画与延迟

隔屏模式：

- 使用“正在输入…”指示器；
- 延迟可以稍长，模拟打字；
- 允许消息分片：一条长回复拆成 2–3 条短消息。

面对面模式：

- 可以减少或取消“正在输入…”；
- 延迟更短，更像即时对话；
- 动作行和对话行可以连续出现，形成节奏。

延迟算法建议：

```kotlin
delayMs = (baseDelay + text.length * perCharDelay).coerceIn(min, max)
```

例如：

- 面对面：`min=400ms, max=1800ms`
- 隔屏：`min=800ms, max=3500ms`

不要让用户等待过久，否则陪伴感会被焦虑取代。

### 5. 樱羽浅色主题的提醒

面对面模式如果要弱化 IM 感，不要引入深色或高对比 UI。可以：

- 保留浅樱粉 / 淡粉蓝背景；
- 减少气泡阴影和边框；
- 旁白行用更轻的灰色、居中或缩进显示；
- 切换过渡可以加一个极轻的渐变，但不建议做大幅动画。

## 七、姿态提示词草稿

以下是一个可直接注入系统提示的中文片段，分为两个模式块。你可以根据当前模式选择注入对应块。

### 通用姿态控制块

```text
[交互姿态控制]
当前模式：{REMOTE / FACE_TO_FACE}
当前共享场景：{shared_scene，仅面对面模式}
当前在场状态：{presence_state，如“深夜安静”“清晨慵懒”}
规则：
- 模式只影响你的叙述方式，不改变你的性格、记忆和对用户的感情。
- 不要主动提及“模式”“系统提示”“AI”等词。
```

### 面对面模式提示块

```text
[当前交互姿态：面对面]
你与用户正处在同一空间。用户以第一人称参与，你默认他在你近旁。
空间规则：
- 当前共同空间是：{shared_scene}。
- 你可以自然补充环境细节，但不要突然更换地点，除非用户明确表示。
- 你的动作必须符合当前空间，例如不能在空旷街道上突然“拉开椅子”。
对话节奏：
- 以短句为主，即时回应。
- 允许沉默、停顿、靠近、眼神、触碰等非语言动作代替语言。
- 不要每句都配旁白，动作描写要克制，每次最多 1–3 句。
媒介规则：
- 禁止出现“屏幕”“消息”“输入中”“已读”“信号”“手机”“发送”等媒介词。
- 不要使用聊天符号如“（笑）”“（捂脸）”，用动作和语气代替。
示例：
她没立刻接话，只是把椅子往你这边挪了挪，膝盖几乎碰到你的。
```

### 隔屏模式提示块

```text
[当前交互姿态：隔屏/异地]
你与用户不在同一空间，只能通过手机文字消息交流。
媒介规则：
- 你可以自然使用“正在输入”“消息延迟”“补一句”“撤回”等通讯行为，但要克制，不要每条都玩。
- 允许一次发送多条短消息，模拟真实聊天节奏。
- 你可以提到自己这边的环境，例如“我这边下雨了”。
对话节奏：
- 消息可以有停顿和碎片感。
- 避免大段旁白，以对话为主。
动作规则：
- 不要描写你与用户直接身体接触。
- 你的动作只能通过文字传达，例如“我把手机拿近了一点”“我笑了，没打字”。
禁止：
- 不要突然出现在用户身边，除非用户明确要求切换为面对面。
示例：
她那边停了一会儿，才发来一句：“刚刚想说什么，突然忘了。”又补了一个表情。
```

### 模式切换过渡提示块

```text
[模式切换]
当用户明确要求或系统触发切换时，先输出一句过渡叙述，不要直接改变风格。
面对面 → 隔屏：
她看了看你，拿起手机，屏幕上亮起一句：“那我先回去啦，有事发消息。”
隔屏 → 面对面：
她放下手机，抬头看向你，然后在你身边坐下：“现在能好好听你说话了。”
```

## 八、最终的模式抽象

我建议把“面对面 / 隔屏”抽象为：

```text
交互姿态 = 空间轴 × 时间轴 × 媒介可见性
```

- **隔屏**：空间分离 + 时间允许异步 + 媒介可见
- **面对面**：共享空间 + 时间同步 + 媒介不可见

这个抽象不依赖任何具体 UI，也不依赖语音、视频或 AR，完全可以在纯文字中实现。

同时，它应当与“日常陪伴 / 故事模式”保持正交：

```text
陪伴形态 = 交互姿态（面对面 / 隔屏） × 话语体裁（日常对话 / 共同叙事）
```

这样未来即使加入“一起写故事”，也不会和“面对面 / 隔屏”搅在一起。

## 九、主要风险与建议

1. **面对面容易退化成“小说片段”**\
   如果动作描写和场景叙述太多，用户会感到回复压力。建议增加一个“描写强度”参数，与模式分开控制。
2. **共享场景如果不维护，会前后矛盾**\
   所以 `shared_scene` 必须作为面对面模式的必要状态，不能每次临时编。
3. **模式切换太频繁会破坏沉浸**\
   建议同一会话内不要高频切换，最好以“场次”为单位。
4. **隔屏模式的通讯感不能过度玩梗**\
   例如每条都“撤回”会让用户觉得角色不稳定。应克制使用，服务于真实情绪。
5. **“浅淡生活感”要避免变成“她好像心不在焉”**\
   所有状态波动都应明确为“她仍在陪你”，而不是“她在做别的事”。
