## 1. 需求理解（用户原话转译）

1. **同卡不同魂**：同一张角色卡开多个会话，每个会话角色在「卡设定的范围」内随机取值，于是性格/偏好各有差异（TAVO 例子：欧派喜好 95/90、接受粗暴 60/25）。
2. **初版平浅、后续拓展多元**：维度体系先做精简版（6 维左右），数据结构留扩展位，后续可加维度。
3. **自补充（关键）**：人设**没提到**的维度（如体育偏好），角色遇到相关话题时**根据性格/经历自行推断并自述**——不是回避，也不是千人一面。
4. **反差感（用户批注，必须的一环）**：除了"表面性格"，角色还要有「另一面」——特定情境下流露出的、与表面形成反差的特质，是深入了解后的惊喜点（"反差萌/立体感"）。

> 本质：把「角色设定」从「一段静态文本」升级为「静态文本 + 会话级隐藏数值 + 反差对 + 动态自述偏好」，叠加成"这个会话独有的灵魂"。

## 2. 设计目标与边界

| 目标 | 说明 |
|---|---|
| 同卡多会话可区分 | 会话列表/聊天中能感知「这个角色的不同之处」 |
| 不崩人设 | 数值只在卡允许的范围内浮动；自补充的偏好与卡设定一致 |
| 数据安全 | 不动 memory_items 表结构；新增独立表，迁移可控 |
| 可扩展 | 维度可增删；自补充沉淀进既有记忆系统，不另起炉灶 |
| 性能影响 ≈0 | 只在建会话/发消息时读一次小表，无热路径开销 |

**边界（不做）**：不做角色间真实"信息差"逻辑（那是 v1.2 套话/互动范畴）；不做 TTS 音色差异化；不做复杂人格状态机。

## 3. 方案架构（三层 + 反差对）

```
┌─────────────────────────────────────────────────┐
│ ① 数据层：conversation_traits 表（会话级独有人格）      │
│    cardId + convId + 6维数值 + 反差对 + 印象摘要        │
├─────────────────────────────────────────────────┤
│ ② 生成层：创建会话时「卡范围 → 随机数值 + 反差对 + 印象摘要」│
│    (1) 6 个基础维度：范围从卡派生，随机落点              │
│    (2) 反差对：表面特质 vs 隐藏特质（卡派生/随机库）       │
│    (3) 印象摘要：把数值+反差+卡设定 → 一句概括该会话角色    │
│        性格的话（第三人称，非自述），写入 traits          │
├─────────────────────────────────────────────────┤
│ ③ 运行时层：Prompt 注入「印象摘要 + 反差 + 自补充引导」   │
│    (1) system 注入印象摘要（角色性格总结）              │
│    (2) 反差触发：特定情境（熟络/被误解/独处）流露另一面    │
│    (3) 自补充：未知偏好话题 → AI 按性格推断并自述 →       │
│        沉淀为该角色的记忆（复用记忆提取管线）              │
└─────────────────────────────────────────────────┘
```

### 3.1 维度设计（初版 6 维，范围 0~100）

| 维度 | 含义 | 卡范围默认 | 示例（小夏） |
|---|---|---|---|
| 外向度 | 主动搭话 vs 被动回应 | 50±20 | 55（比默认略主动） |
| 主动度 | 话题推进 vs 跟随 | 50±25 | 60 |
| 温度 | 热情 vs 冷淡 | 卡个性派生 | 85（温柔） |
| 依恋度 | 亲近倾向 vs 距离感 | 50±25 | 70 |
| 幽默感 | 爱玩 vs 正经 | 50±25 | 40（温柔学姐偏正经） |
| 随性度 | 随意 vs 讲究 | 50±25 | 30（讲究） |

#### 3.1.1 卡范围派生：支持三类捏卡用户（用户批注）

用户捏卡时的设定方式不同，范围派生须兼容三种输入（对应三类用户）：

| 用户类型 | 设定方式 | 范围派生方式 | 初版实现 |
|---|---|---|---|
| **数据党** | 精确填中间值 + 浮动范围 | 直接读用户填的数值 | ✅ 角色卡新增可选 `traitsRange` 字段（见下） |
| **感觉党** | 用概括性描述（"温柔体贴""有点小脾气"） | 数值判定难 → 需从文本推导 | 初版：关键词启发式兜底；**后续：LLM 读卡生成范围（送审难点 B）** |
| **中间党** | 部分维度精确、部分模糊 | 混用 | 支持字段部分填值，未填维度走启发式/兜底 |

- **角色卡新增可选字段**（不影响既有卡，不填则走启发式）：
  ```
  traitsRange: Map<String, IntRange>?  // 例：{ "warmth": 70..95, "humor": 20..50 }
  ```
- **启发式兜底**：导入的 Tavern 卡 / 未填范围的卡，用 `personality` 关键词给默认范围（「温柔」→温度+20；「毒舌」→幽默感+20），无信号则 50±25。
- **随机落点**：`SecureRandom` 在范围均匀取值，写入 `conversation_traits`（每会话一条，建会话时生成一次，之后固定不漂移）。

> 后续拓展：维度可加；`traitsRange` 可升级为角色卡编辑 UI 里「数值/描述」两种输入模式（数据党/感觉党/中间党选择器），见 P4。

### 3.2 反差对（用户批注：反差感）

**问题**：只有"表面性格"，角色显得单薄。反差感 = 角色有另一面，特定情境下才流露，是深入了解后的惊喜。

**方案**：每个会话角色生成 **1 组反差对**（表面特质 vs 隐藏特质），随 traits 存储：

```
contrastSurface  TEXT  # 表面特质（平时给人的感觉）
contrastInner    TEXT  # 隐藏特质（特定情境下流露的另一面）
contrastTrigger  TEXT  # 触发情境描述（如：熟络之后/被误解时/深夜独处）
```

**生成方式**（建会话时）：
1. **卡派生**：从卡设定提取表面特质；隐藏特质从「内置反差库」里选 1 个与卡不冲突的（如温柔卡 → 反差库候选「倔强/腹黑/依赖/要强」中选）
2. **兜底**：LLM 失败时用随机库 + 固定模板

**注入方式**（Prompt）：
> 「你平时给人的感觉是{contrastSurface}。但在{contrastTrigger}时，你会不经意流露{contrastInner}的一面。」

**触发联动**：反差流露的频繁程度可与「依恋度」联动——依恋度越高越容易流露内在（深入了解后的亲近感）；也可做成「好感度/互动」阶段性解锁（更远期，P4 候选）。

**示例（小夏某会话）**：表面「温柔体贴的学姐」，隐藏「其实很要强，被小看时会倔强地证明自己」，触发「被误解或低估时」。→ 同样是温柔学姐，不同会话的"另一面"不同，制造反差感。

> 反差对是本方案**最有设计深度的点**之一，具体机制（生成策略/触发逻辑/与好感度联动）**送专家评审（§9-A）**。

### 3.3 印象摘要（会话级画像，区分的关键 —— 用户批注已纠正定位）

**定位纠正（v2）**：独白**不是**角色第一人称自述（"我是小夏，我更喜欢……"），而是**对该会话角色性格/言行的概括总结**（第三方视角），类似你在 TAVO 上对会话角色的备注印象（"软软的xx""暖暖的xx"——但不是照抄这个例子，而是这个"概括定位"）。

**生成物**：一段第三人称的概括 + 2~3 个印象标签：
> 例：「慢热·暖心」｜「平时温柔体贴，但初识时话不多，熟了以后才会真正敞开心扉。有点小倔强，被小看时会努力证明自己。」

**生成时机**：创建会话时，把「卡设定 + 6 维数值 + 反差对」交给 LLM 生成。**降级**：LLM 失败 → 纯模板（由数值区间 + 标签库拼装，如 `温度≥75 → "暖心"`、`依恋≥70 → "粘人"`）。

**展示**：
- ①会话列表卡片显示标签行（一眼区分多个同卡会话）
- ②聊天页角色信息 / 记忆面板可查看完整摘要
- ③**用户可手动改印象**（类比 TAVO 备注，用户自己写的印象优先）——存储为 `identityBlurb`，用户修改后 `generatedBy='user'` 不再被覆盖

> 性质：这是"角色的档案/印象卡"，**不是角色说的话**。展示给用户看、也注入 prompt 作为角色性格总结。

### 3.4 自补充（核心机制，初版可行，后续优化位已标）

**问题**：卡没写运动偏好，角色被问到「你喜欢什么运动？」时怎么办？
**方案**：两段式——

1. **Prompt 注入引导**：在 system 加入一段「未知偏好处理」规则：
   > 「当被问到你的人设里没有明确写到的偏好（如喜欢的食物/运动/音乐等）时，不要笼统回避，而要根据你的性格、背景、过往经历合理推断并自然地说出来。你说出口的偏好会自动成为你的记忆，以后保持一致。」
2. **沉淀**：角色说出的推断偏好 → 走既有记忆提取管线 → 以该角色名义存入记忆（`SHARED`）→ 后续 prompt 注入，形成「越聊越具体、且自洽」的偏好库。

**效果**：小夏（温柔/爱读书）被问运动 → 推断「喜欢瑜伽/散步这类安静运动」并记住；阿杰（毒舌/技术宅）→ 推断「宅在家打游戏/偶尔夜跑」并记住。**同卡不同会话也能因初始数值不同而推断出不同细节**。

**初版 OK，后续优化方向（P4，用户批注认可初版）**：
- 一致性校验：已沉淀偏好间不互相矛盾（复用记忆更正机制）
- 主动引用：不只被动回答，合适时机主动提及已沉淀偏好（方案 F 遗留点）
- 与 6 维数值联动：数值影响推断方向（如随性度低 → 推断"讲究、注重细节的偏好"）

### 3.5 数据模型（新增，不动既有表）

```
conversation_traits
├── id              PK
├── conversationId    FK → conversations.id（唯一）
├── characterCardId   FK → character_cards.id
├── extroversion     INT  0~100   # 6 维数值
├── initiative       INT
├── warmth           INT
├── attachment       INT
├── humor            INT
├── casualness       INT
├── contrastSurface  TEXT        # 反差对·表面特质
├── contrastInner    TEXT        # 反差对·隐藏特质
├── contrastTrigger  TEXT        # 反差对·触发情境
├── identityBlurb    TEXT        # 印象摘要（第三人称概括）
├── identityTags     TEXT        # 印象标签（逗号分隔，2~3 个）
├── generatedBy      TEXT        # 'data_range' / 'heuristic' / 'llm' / 'user'
└── createdAt        LONG
```

- **角色卡**：新增可选 `traitsRange`（数据党用），JSON 字段，不进必填校验。
- **迁移**：Room `v24 → v25`，建新表（无存量数据，安全）。
- **DAO**：`getByConversation(convId)` / `insert` / `updateBlurbAndTags`。
- **兼容**：老会话无 traits → 视为「未差异化」（行为与现在一致），可选后台懒生成（默认不做）。

| 风险 | 应对 |

## 9. 专家评审结论（2026-08-28 基于 WebSearch 查证，无需 pro）

> 通过 WebSearch 查证业界做法后，两处难点已有明确结论。评审可关闭。

### §9-A 反差感机制 —— 结论：双层人格 + 数值条件触发

**业界查证**：
- [NebulaBlock: From NPC to Persona](https://blog.nebulablock.com/from-npc-to-persona-how-to-build-depth-in-ai-roleplay-characters/)：「Surface traits 是可见外表；hidden traits 在压力/亲密下浮现」「以条件触发嵌入，如 trust exceeds 70%」——**与我的方案方向一致**。
- SillyTavern 角色指南：多层次性格构建（表层/核心/隐藏，特定条件才展现）——同一思路。
- ImagiPortal：「深度人格不来自更多形容词，而来自 pressure, contradiction, voice, memory」——印证反差/矛盾是核心。

**最终定案**：
1. **生成策略**：卡派生表面 + 受限反差库选隐藏（一致性过滤），**不用全随机、不依赖 LLM 自由生成**（可控性最好）。
2. **触发机制**：**数值联动优先于固定情境**——依恋度（或好感度）≥ 阈值时开始流露隐藏特质，与业界 "trust threshold" 一致；固定情境作为兜底补充。
3. **一致性过滤**：反差库候选与卡设定做关键词冲突检测（如卡含「温柔」时排除「暴虐」类），冲突则重选。
4. **初版范围**：1 组反差对 + 依恋度阈值触发；「好感度/互动阶段性解锁更深反差」列为 P4。

### §9-B 感觉党卡范围派生 —— 结论：初版就走 LLM 读卡（启发式仅兜底）

**业界查证**：
- [CharacterGPT (NAACL 2025)](https://aclanthology.org/anthology-files/anthology-files/anthology-files/pdf/naacl/2025.naacl-industry.24.pdf)：用 CPT 从章节摘要提取 8 类结构化 trait，**结构化 trait 显著提升角色一致性与准确率**——证明 LLM 读文本转结构化数值是成熟且有效的。
- [EgoEchoAgentSummarizer](https://gist.github.com/mafulafunk/907f28aa5e8f5666213ba37e9921867f)：LLM 提取 trait（category/facet/degree/confidence）的成熟实现范式。
- 无业界成熟词表可供「模糊描述→数值」直接映射 → **启发式只能兜底，不能主用**。

**最终定案**：
1. **初版主路线：LLM 读卡生成范围**——建卡保存时（或首次建会话时）让 LLM 读卡 `personality/description`，输出 6 维数值范围 JSON（带 confidence）；失败降级关键词启发式 + 50±25 兜底。
2. **生成时机**：**建卡时生成一次并存卡上**（优于建会话时——一次成本、全会话复用、用户可编辑），卡上存 `traitsRange`。
3. **降级策略**：LLM 失败 → 关键词启发式 → 50±25 默认，三级兜底。
4. **数据模型确认**：`traitsRange` 部分可选（数据党全填 / 感觉党全空走 LLM / 中间党部分填），合理。
